# open-banking-rails-kotlin

Kotlin / Spring Boot 3 rebuild of [open-banking-rails](https://github.com/softberries/open-banking-rails). It is a behaviour-parity
migration: the Ruby specs and the runtime oracle in [`migration-spec/`](migration-spec/) define what "done" means.

Stack: Kotlin on JVM 21, Spring Boot 3.5 (Web MVC, Data JPA/Hibernate, Security, Validation, Mail), Flyway, JTE templates,
JobRunr (jobs on PostgreSQL), springdoc-openapi, PostgreSQL 17, Gradle Kotlin DSL with a version catalog, ktlint, detekt, Kover.
Tests use JUnit 5, Kotest assertions, MockK/springmockk and Testcontainers.

## Run

```bash
# PostgreSQL 17 for development (database open_banking_rails_development)
docker run -d --name obr-pg -p 5432:5432 -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=open_banking_rails_development postgres:17

./gradlew bootRun                   # http://localhost:3000, profile "development" (RAILS_ENV unset)
curl -i http://localhost:3000/up    # liveness probe
```

Production runs from `docker-compose.prod.yml`: `docker compose -f docker-compose.prod.yml up -d`. Services:
- `db` (postgres:17).
- `migrate`: a one-shot service. It writes a pre-migration `pg_dump` into `./backups`, then runs Flyway via `java -jar app.jar db:migrate`.
- `app`: healthcheck `curl -fsS http://127.0.0.1:3000/up`.
- `db-backup`: `BACKUP_SCHEDULE`, keeps 7 daily, 4 weekly and 6 monthly dumps.
- `restore` (profile `restore`).

There is no Redis and no separate worker. On first boot `bin/docker-entrypoint` generates `SECRET_KEY_BASE` and the three
`ACTIVE_RECORD_ENCRYPTION_*` secrets into the `app_secrets` volume. The volume uses the same paths (`/rails/secrets`) and uid 1000 as the
Ruby image, so an existing Ruby volume is reused as is.

Build the image with a release tag: `docker build --build-arg APP_VERSION=v1.2.3 .`. The tag is written to `/rails/VERSION`, and the footer
shows `1.2.3`. Without the build arg it shows `dev`.

## Test

```bash
./gradlew ktlintCheck build    # ktlint + detekt + tests (Testcontainers needs Docker) + Kover
./gradlew test --tests '*UpEndpointTest'
./gradlew ktlintFormat         # fix formatting
```

Integration tests extend `support.IntegrationTest`. It provides one `postgres:17` container per JVM, migrated once, with every table except
`flyway_schema_history` truncated before each test. It defaults to `APP_TIME_ZONE=UTC` and `OTEL_SDK_DISABLED=true`; override either with
`@TestPropertySource`. On a remote Docker host, export `TESTCONTAINERS_HOST_OVERRIDE`. Set `TESTCONTAINERS_RYUK_DISABLED=true` when Ryuk cannot run.

## Environment variables

The Kotlin service keeps the Ruby ENV names (`migration-spec/docs/70-security-and-config.md` section 11). `app.*` values are bound through
`AppProperties` (relaxed binding: `APP_HOST` → `app.host`). In the table, "M-0xx" names the unit that implements the behaviour; this
skeleton only binds the value.

| Variable | Default | Kotlin meaning |
|---|---|---|
| `DATABASE_URL` | – | Rails URL form `postgres://user:pass@host:5432/db?params`, mapped to `spring.datasource.url` (`jdbc:postgresql://host:5432/db?params`), `username` and `password`. Wins over `POSTGRES_*`. Required by `bin/docker-migrate` |
| `POSTGRES_HOST` | `localhost` | Datasource host when `DATABASE_URL` is unset |
| `POSTGRES_PORT` | `5432` | Datasource port |
| `POSTGRES_USER` | `postgres` | Datasource user. Compose uses it (default `obr`) to build `DATABASE_URL` and to initialise `db` |
| `POSTGRES_PASSWORD` | `postgres` | Datasource password (compose default `obr`) |
| `POSTGRES_DB` | `open_banking_rails_development` | Database name in development. The `test` profile always uses `open_banking_rails_test`. Compose default `obr_production` |
| `PORT` | `3000` | `server.port` |
| `RAILS_MAX_THREADS` | `5` | Hikari `maximum-pool-size` (Ruby DB pool size) |
| `RAILS_LOG_LEVEL` | `info` | `logging.level.root` |
| `RAILS_ENV` | `development` | Selects the Spring profile (`development`, `test`, `production`) unless `SPRING_PROFILES_ACTIVE` is set. The image sets `production` |
| `SECRET_KEY_BASE` | – (generated by the entrypoint) | `AppProperties.secretKeyBase`. The `production` profile fails at boot without it. Signs sessions, OAuth state and Turbo streams (M-006, M-018, M-036) |
| `ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY`, `ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY`, `ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT` | – (generated by the entrypoint) | Rails-compatible encryption of secrets at rest (M-011). Use the same values as the Rails deployment |
| `APP_HOST` | unset (`localhost:3000` for links) | Public host[:port] for absolute links. Also the allowed host when `APP_HOSTS` is unset. Enforced by M-002 |
| `APP_HOSTS` | unset | Comma-separated allowed `Host` headers. When set but empty (compose default) the host check is off, as in Ruby. Enforced by M-002 |
| `APP_PROTOCOL` | `https` (compose: `http`) | Scheme of absolute links (M-002) |
| `FORCE_SSL` | `true` (compose: `false`) | Only the exact string `true` enables HTTPS redirect, HSTS and secure cookies (M-002) |
| `APP_TIME_ZONE` | `Europe/Warsaw` | **New (D-007).** IANA zone for "today", periods and schedules (`AppClock`). Timestamps stay stored in UTC. An invalid id fails startup |
| `APP_VERSION` | `dev` | Docker build arg. Written to `VERSION`. `AppProperties.version` strips a leading `v` |
| `SMTP_ADDRESS`, `SMTP_PORT`, `SMTP_DOMAIN`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_AUTHENTICATION`, `SMTP_STARTTLS` | blank | Outgoing mail (password reset unit). Passed through by compose |
| `LLM_MERCHANT_AUTO_APPROVE_THRESHOLD` | `0.85` | LLM auto-approve threshold (LLM unit) |
| `PSU_IP_ADDRESS`, `PSU_USER_AGENT` | – | Optional Enable Banking request headers (Enable Banking unit) |
| `OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_*`, `OTEL_*_EXPORTER`, `OTEL_SDK_DISABLED` | SDK defaults | OpenTelemetry Spring Boot starter, read as is (configured by M-010). Tests set `OTEL_SDK_DISABLED=true` |
| `SECRETS_DIR` | `/rails/secrets` | Entrypoint only: where generated secrets are persisted (mode 600) |
| `BACKUPS_DIR` | `/rails/backups` | `bin/docker-migrate` only: target of the pre-migration dump |
| `BACKUP_SCHEDULE`, `BACKUP_KEEP_DAYS`, `BACKUP_KEEP_WEEKS`, `BACKUP_KEEP_MONTHS` | `@daily`, 7, 4, 6 | Compose only (`db-backup`) |
| `APP_TAG`, `APP_PORT`, `COMPOSE_FILE` | `latest`, `3000`, – | Compose only |
| `REDIS_URL`, `REDIS_PORT` | – | **Not used.** Jobs run on JobRunr/PostgreSQL and Turbo Streams need no Redis (D-001, D-004) |
| `WEB_CONCURRENCY`, `PIDFILE` | – | **Not used** (Puma-specific; Tomcat runs one process) |
| `SECRET_KEY_BASE_DUMMY` | – | **Not used** (the image build needs no secrets) |
| `CI` | – | **Not used** (Rails eager-load switch) |
| `BUNDLE_*`, `RUBY_VERSION`, `RUBY_DEBUG_*`, `ANNOTATERB_SKIP_ON_DB_TASKS` | – | **Not used** (Ruby tooling) |

## Database

`src/main/resources/db/migration/V1__baseline.sql` is the final Rails schema (`db/schema.rb` version `2026_05_14_141323`) plus the
`ledger_entries` view v04. The `gutentag_*` tables are left out (D-006). On an existing Rails database (with the 33 `schema_migrations` rows), Flyway's
`baselineOnMigrate` (`baselineVersion=1`) records V1 as the baseline, re-applies nothing and leaves the Rails tables (`schema_migrations`,
`ar_internal_metadata`, `gutentag_*`) untouched. Hibernate runs with `ddl-auto=validate` and `hibernate.jdbc.time_zone=UTC`.
